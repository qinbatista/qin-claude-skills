# Task Lifecycle

Standing rule: never hand the work back — never ask clarifying questions, never offer option menus, never stall waiting for an answer, and never make Qin read or confirm something to let you continue. Take the most reasonable reading, state the assumption, finish the whole task, and put every doubt, assumption, and alternative in the final report at the END — stated, never offered: write "not done: X, because Y", never "要不要我…?" or "shall I…?". The only exception is an irreversible outward action the request does not imply (push, publish, deploy to something shared, send a message, delete outside the task's scope): finish everything else, then name it for authorization.

Every task MUST start the `task-lifecycle` skill (`~/.claude/skills/task-lifecycle/SKILL.md`) FIRST, before any other tool call, and follow it end to end. Every task means every task — code, prompt, document, config, script, question, research, review, deployment; no task is too small or too text-only. The flow is: connect Obsidian (read the vault's own rules first; never change its structure) → plan + difficulty (simple/standard/complex; scope the memory lookup by project + module, and for code by file + method/symbol; a repeated same-session correction re-plans with a changed approach) → announce (difficulty+score · model · steps · skills, a standalone message in the user's language, only after the plan is fixed; material mid-task plan changes get their own notice) → execute result-first with Qin's style rules (any code: the four-stage writing gate in `references/code-style/code-writing-philosophy.md` first, then `references/code-style/` design + language rules, plus the UI gate and User Experience Philosophy for UI work, plus a bounded producer Quick Check before presenting; any prompt: `references/prompt-style/`) → present `MAIN RESULT READY`, then REAL verification — required by default, exempt only as a stated low-risk single-result task — as ONE independent verification pass carrying the whole check list, looped until PASS (FAIL → exact evidence → the producer fixes, never the verifier → fresh re-verification of the original check; ≈3 fails → change approach or honestly report BLOCKED; never claim done with unrun/failing checks) → post-task code/process optimization → record a complete change memory (what/why/result/verification/decisions/risks/files/module+symbol) to the Obsidian vault per its own schema, after confirming process contract, execution evidence, and existing memory agree, and read it back — NEVER write memory files (`Memory/` or any notes) into the project repo. Intermediate artifacts go to `<project>/Cache/<Category>/<task>/`, never scattered.
